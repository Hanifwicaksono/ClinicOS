Ruang lingkup
Digitalisasi layanan klinik di Indonesia terus berkembang, namun masih banyak klinik yang menghadapi kendala dalam pelayanan sehari-hari. Proses pendaftaran, pengelolaan antrean, dan pencatatan rekam medis sering kali masih dilakukan secara manual atau menggunakan sistem yang terpisah-pisah, sehingga memakan waktu dan rawan kesalahan. Di sisi pasien, sistem antrean umumnya hanya menampilkan nomor yang sedang dipanggil. Pasien tidak memiliki gambaran kapan gilirannya tiba, sehingga memilih menunggu lama di klinik dan membuat ruang tunggu menjadi padat.
ClinicOS adalah platform Software as a Service (SaaS) multi-tenant berbasis web yang mengintegrasikan registrasi pasien, appointment, visit, antrean realtime, rekam medis elektronik, resep, billing, laporan, serta audit log. Produk terdiri atas Staff Web untuk owner/admin, resepsionis, dokter, dan kasir, serta Patient Web untuk pencarian klinik, booking, reminder, dan pemantauan antrean. Kedua antarmuka diakses melalui browser responsif pada PC, laptop, tablet, atau smartphone tanpa aplikasi mobile native dan tanpa aplikasi desktop terpisah. Tenant dan cabang memiliki pembatasan data dan permission yang divalidasi di backend.
Predictive Queue menampilkan rentang estimasi waktu antrean beserta tingkat keyakinan, bukan janji jam pelayanan yang pasti. Dukungan layanan mencakup poli umum dan poli gigi, termasuk odontogram, peringatan alergi kritis, serta RME dengan alur Draft, Autosave, Finalize, dan Amendment. Cloud Mode menjadi mode utama. Resilient Edge Mode menggunakan satu Edge Node lokal di LAN klinik agar workflow yang ditetapkan dapat berjalan saat koneksi WAN terganggu dan disinkronkan secara aman setelah pulih. Edge Node adalah komponen server lokal, bukan aplikasi desktop untuk pengguna.
Desain
 Umum
ClinicOS menggunakan arsitektur SaaS berbasis web dengan dua frontend React (Staff Web dan Patient Web), backend/API Laravel modular monolith, database MySQL, serta Redis dan Laravel Reverb/WebSocket untuk cache, antrean pekerjaan, dan realtime. Cloud merupakan pusat layanan. Cabang yang mengaktifkan Resilient Edge Mode memakai Local API/DB dan Sync Agent pada Edge Node melalui LAN. Semua pengguna tetap mengakses UI menggunakan browser.
Antarmuka web: Staff Web menyediakan workspace berdasarkan role/capability bagi owner/admin, resepsionis, dokter, dan kasir. Patient Web menyediakan discovery klinik, appointment, booking, dan live queue. Keduanya responsif di browser desktop maupun smartphone. Public queue display juga dibuka melalui browser.
Backend Laravel menjalankan autentikasi, tenant/branch isolation, otorisasi berbasis capability, modul patient/doctor/service, appointment dan visit, queue state, Predictive Queue, RME General/Dental, resep, billing/payment, laporan, notifikasi, serta audit log. Realtime bertugas mengirim pembaruan, sedangkan API/database menjadi sumber kebenaran.
Database MySQL menyimpan data operasional yang dipisahkan sesuai scope tenant dan branch. Operasi kritis seperti pembayaran dan pembuatan visit menerapkan idempotency, sedangkan perubahan RME yang sudah difinalisasi dicatat melalui amendment dan audit log.
Edge Node (opsional sesuai penerapan) menyediakan Local API/DB, sinkronisasi, dan realtime LAN untuk workflow cabang yang ditentukan ketika WAN terganggu. Pengguna tetap mengakses layanan melalui browser, bukan perangkat lunak desktop khusus.
Gambaran umum sistem ditunjukkan pada gambar berikut
:
Alur pelayanan utama pada ClinicOS adalah sebagai berikut:
Pasien mencari klinik, memilih layanan/jadwal, dan booking melalui Patient Web; resepsionis juga dapat mendaftarkan pasien walk-in lewat Staff Web.
Sistem memvalidasi slot, membuat atau menautkan Visit saat check-in, dan memperbarui state antrean realtime tanpa duplikasi.
Pasien memantau status antrean dan rentang estimasi waktu melalui Patient Web, serta menerima notifikasi sesuai konfigurasi.
Resepsionis mengelola Call, Skip, Start, dan Complete; layar antrean publik hanya menampilkan data non-sensitif.
Dokter mencatat RME General/Dental, alergi kritis, odontogram bila relevan, dan resep; finalisasi serta koreksi dicatat berversi.
Kasir memproses tagihan dan pembayaran secara idempotent, menerbitkan receipt, dan data layanan masuk ke laporan serta audit log. Saat WAN bermasalah, workflow Edge yang didukung disinkronkan kembali setelah koneksi pulih.

Produk

Monitoring dan Evaluasi
 
Monitoring dilakukan setiap sprint melalui Product Backlog, Sprint Backlog, daily/weekly coordination, Sprint Review, dan Retrospective. Evaluasi akhir mencakup aspek teknis, penggunaan, dan bisnis. Indikator ketercapaian yang digunakan:
• Minimal 90% kebutuhan prioritas tinggi pada backlog berbasis MF-1 sampai MF-7 dapat didemonstrasikan melalui Staff Web dan Patient Web responsif sesuai permission tiap role.
• Tenant isolation dan backend authorization diuji lintas dua tenant/cabang, termasuk penolakan akses yang tidak sah dan pencatatan audit aksi sensitif.
• Pengujian retry booking/check-in/payment membuktikan tidak terjadi Visit atau pembayaran ganda, dan perubahan RME Finalized memakai amendment/version.
• Realtime queue diuji pada beberapa browser, termasuk state Waiting/Called/Skipped/In service/Done, fallback stale/refetch, dan rentang ETA Predictive Queue.
• Resilient Edge Mode diuji saat WAN putus/pulih pada LAN yang sehat, dengan sinkronisasi idempotent dan indikator stale/conflict; target SRS: 95% backlog normal tersinkron dalam 2 menit setelah reconnect.
